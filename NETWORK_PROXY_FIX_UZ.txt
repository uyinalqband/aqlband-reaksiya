TELEGRAM ICHIDAGI apiErrors.network TUZATISHI

ZIP ichidagi papka tuzilishini o‘zgartirmasdan barcha fayllarni GitHub
repository ildiziga yuklang va mavjud fayllarni almashtiring.

Muhim:
1. functions/api/platform.ts aynan repository ildizidagi functions/api/
   papkasida turishi kerak. Bu Supabase funksiyasi emas, Cloudflare Pages
   Function hisoblanadi.
2. Cloudflare Pages’da yangi deployment tugashini kuting.
3. Supabase SQL Editor’da hech narsa ishga tushirish shart emas.
4. aqlband-api Edge Function’ni va TELEGRAM_BOT_TOKEN’ni qayta o‘zgartirish
   shart emas.

Tekshirish:
- Deploymentdan keyin brauzerda
  https://aqlband-reaksiya.pages.dev/api/platform
  manzilini oching.
- {"ok":false,"error":{"code":"method_not_allowed","message":"Use POST"}}
  ko‘rinishidagi javob chiqishi kerak. Bu xato emas: brauzer GET yuboradi,
  ilova esa kerakli POST so‘rovini yuboradi.
- So‘ng Telegram ilovasini butunlay yoping, qayta oching va Reyting
  sahifasidagi “Qayta urinish” tugmasini bosing.

Tuzatish qanday ishlaydi:
- Telegram WebView endi boshqa domenga to‘g‘ridan-to‘g‘ri murojaat qilmaydi.
- So‘rov Cloudflare’dagi shu domenning /api/platform yo‘li orqali Supabase’ga
  uzatiladi.
- Proksi hali ishga tushmagan yoki Supabase’ga ichki so‘rovi vaqtincha
  bajarilmagan holatda ilova avtomatik ravishda to‘g‘ridan-to‘g‘ri Supabase
  so‘roviga qaytadi.
- Foydalanuvchiga endi apiErrors.network texnik kaliti emas, tushunarli
  mahalliylashtirilgan xabar ko‘rsatiladi.
